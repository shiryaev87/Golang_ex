# Вопросы на собеседовании: массивы и слайсы в Go

Вопросы расположены примерно от базовых к более сложным. Примеры можно использовать для самостоятельной проверки.

## Базовый уровень

### 1. Чем массив отличается от слайса?

**Ответ:** у массива фиксированная длина, которая является частью типа. Слайс — это описание участка массива; его длина может меняться.

```go
var a [3]int // массив типа [3]int
s := []int{1, 2, 3} // слайс типа []int
```

Типы `[3]int` и `[4]int` — разные типы. Длина не входит в тип слайса.

### 2. Как объявить массив и слайс?

**Ответ:**

```go
var a [3]int
b := [3]int{10, 20, 30}
c := [...]int{10, 20, 30} // длину массива определяет Go

var s []int
t := []int{10, 20, 30}
u := make([]int, 3) // длина 3, элементы изначально равны нулю
```

В записи `[3]int` число задаёт длину массива, а в `[]int` длина не указана — это слайс.

### 3. Какие нулевые значения у массива и слайса?

**Ответ:** элементы массива получают нулевые значения своего типа. Нулевое значение слайса — `nil`.

```go
var a [2]int
var s []int

fmt.Println(a)       // [0 0]
fmt.Println(s == nil) // true
```

### 4. Что возвращают `len` и `cap`?

**Ответ:** `len(s)` — число элементов в слайсе, `cap(s)` — сколько элементов доступно от начала слайса до конца его базового массива.

```go
a := [5]int{10, 20, 30, 40, 50}
s := a[1:3]
fmt.Println(len(s), cap(s)) // 2 4
```

Слайс `s` содержит два элемента, но от его начала в исходном массиве доступны ещё четыре элемента.

### 5. Что означает выражение `a[low:high]`?

**Ответ:** оно выбирает элементы от индекса `low` включительно до `high` не включительно.

```go
a := [5]int{10, 20, 30, 40, 50}
fmt.Println(a[1:4]) // [20 30 40]
```

Для корректного среза границы должны быть допустимы для массива или слайса; иначе во время выполнения будет panic.

### 6. Можно ли добавить элемент в массив через `append`?

**Ответ:** нет, `append` принимает слайс. Чтобы получить слайс из массива, можно взять его срез:

```go
a := [2]int{10, 20}
s := a[:]
s = append(s, 30)
```

Важно присваивать результат `append` обратно: он возвращает слайс, который может указывать на новую область памяти.

## Средний уровень

### 7. Что произойдёт, если изменить элемент слайса, полученного из массива?

**Ответ:** изменится соответствующий элемент массива, потому что слайс ссылается на его участок.

```go
a := [3]int{1, 2, 3}
s := a[1:]
s[0] = 99
fmt.Println(a) // [1 99 3]
```

Другие слайсы, разделяющие этот участок массива, также увидят изменение.

### 8. Что выведет этот код?

```go
a := [4]string{"John", "Paul", "George", "Ringo"}
x := a[0:2]
y := a[1:3]
y[0] = "XXX"

fmt.Println(x)
fmt.Println(y)
fmt.Println(a)
```

**Ответ:**

```text
[John XXX]
[XXX George]
[John XXX George Ringo]
```

Слайсы `x` и `y` перекрываются на элементе `a[1]`. Запись через `y[0]` меняет именно этот элемент.

### 9. Что копируется при присваивании слайса?

**Ответ:** копируется небольшой дескриптор слайса, а не сами элементы. Дескриптор содержит ссылку на данные, длину и вместимость. Поэтому два слайса могут ссылаться на один базовый массив.

```go
a := []int{1, 2, 3}
b := a
b[0] = 99
fmt.Println(a) // [99 2 3]
```

### 10. Как работает `append` и когда он выделяет новую память?

**Ответ:** `append` добавляет элементы и возвращает новый слайс. Если в базовом массиве хватает вместимости, функция может использовать ту же память; если нет — выделяет новый массив и копирует туда элементы.

```go
a := make([]int, 1, 3)
a[0] = 10
b := append(a, 20)
b[0] = 99
fmt.Println(a[0]) // 99: в этом примере вместимости хватило
```

После перераспределения памяти изменения нового слайса не меняют прежний массив. Точный алгоритм и коэффициент роста вместимости — деталь реализации; на них не следует полагаться.

### 11. Чем отличаются `var s []int`, `[]int{}` и `make([]int, 0)`?

**Ответ:** все три слайса имеют длину 0, но первый — `nil`, а два остальных — ненулевые пустые слайсы.

```go
var a []int
b := []int{}
c := make([]int, 0)

fmt.Println(a == nil) // true
fmt.Println(b == nil) // false
fmt.Println(c == nil) // false
```

Все три можно передавать в `append` и использовать как пустые слайсы. При сериализации различие может быть важно: конкретное поведение зависит от используемого формата и библиотеки.

### 12. Как скопировать элементы слайса?

**Ответ:** встроенной функцией `copy`. Она копирует не большее из длин исходного и целевого слайсов число элементов и возвращает количество скопированных элементов.

```go
src := []int{1, 2, 3}
dst := make([]int, len(src))
n := copy(dst, src)

fmt.Println(dst, n) // [1 2 3] 3
```

`copy` также корректно работает с перекрывающимися участками.

### 13. Что будет, если присвоить один слайс другому и затем вызвать `append`?

**Ответ:** результат зависит от вместимости исходного слайса.

- Если вместимости хватает, добавление использует общий базовый массив. Элементы за длиной одного слайса могут стать видны через другой слайс, если увеличить его длину.
- Если вместимости не хватает, `append` выделяет новый массив. Новый слайс больше не разделяет массив со старым.

Поэтому нельзя судить о разделении памяти только по факту присваивания слайса; важно учитывать `cap`.

### 14. Передаются ли массивы и слайсы в функции по ссылке?

**Ответ:** в Go аргументы передаются по значению.

- При передаче массива копируется весь массив.
- При передаче слайса копируется его дескриптор, который указывает на те же элементы.

Поэтому функция может изменить элементы общего базового массива через слайс, но её присваивание параметру нового слайса само по себе не заменит слайс у вызывающего кода. Чтобы изменить слайс вызывающей стороны (например, его длину после `append`), обычно возвращают результат:

```go
func add(s []int, value int) []int {
	return append(s, value)
}

s := []int{1, 2}
s = add(s, 3)
```

## Продвинутый уровень

### 15. Что такое полное выражение среза?

**Ответ:** форма `s[low:high:max]` задаёт не только длину, но и вместимость результата. Его длина равна `high - low`, вместимость — `max - low`.

```go
a := [5]int{10, 20, 30, 40, 50}
s := a[1:3:4]
fmt.Println(s, len(s), cap(s)) // [20 30] 2 3
```

У такого слайса вместимость ограничена. Дополнительный `append` не сможет затронуть элементы массива за заданной верхней границей: при нехватке вместимости будет выделен новый массив.

### 16. Можно ли сравнивать слайсы оператором `==`?

**Ответ:** два слайса нельзя сравнивать между собой через `==`; такое сравнение не компилируется. Слайс можно сравнить с `nil`.

```go
var s []int
fmt.Println(s == nil) // допустимо
```

Чтобы сравнить элементы двух слайсов, нужно сравнить их длины и элементы вручную или использовать подходящую функцию стандартной библиотеки, например `slices.Equal` в поддерживаемых версиях Go.

### 17. Что копируется в цикле `for range` по слайсу?

**Ответ:** на каждой итерации значение элемента копируется в переменную цикла. Изменение этой переменной само по себе не меняет элемент слайса.

```go
s := []int{1, 2, 3}
for _, value := range s {
	value = 0
}
fmt.Println(s) // [1 2 3]
```

Чтобы изменить элементы, используйте индекс:

```go
for i := range s {
	s[i] = 0
}
```

### 18. Как удалить элемент из слайса?

**Ответ:** обычно сдвигают последующие элементы влево и уменьшают длину слайса:

```go
i := 1
s = append(s[:i], s[i+1:]...)
```

Это сохраняет порядок элементов, но может оставить ссылку на прежнее значение в неиспользуемой ячейке базового массива. Если слайс содержит указатели или другие ссылки и важно освободить объект для сборщика мусора, очистите последнюю ячейку после сдвига:

```go
copy(s[i:], s[i+1:])
s[len(s)-1] = nil // для слайса указателей; тип значения должен допускать nil
s = s[:len(s)-1]
```

Для слайсов значений, допускающих `nil`, вместо `nil` следует записать нулевое значение соответствующего типа.

### 19. Как слайс может неожиданно удерживать большой массив в памяти?

**Ответ:** маленький слайс может ссылаться на часть большого массива. Пока слайс достижим, базовый массив может оставаться в памяти.

```go
small := big[100:110]
```

Если нужны только выбранные элементы надолго, можно скопировать их в отдельный слайс:

```go
smallCopy := append([]int(nil), big[100:110]...)
```

После этого `smallCopy` не зависит от базового массива `big`.

### 20. Безопасно ли одновременно читать и изменять один слайс из разных горутин?

**Ответ:** не обязательно. Одновременный доступ к общим элементам, когда хотя бы один доступ — запись, без синхронизации может привести к data race. Обычный слайс не обеспечивает потокобезопасность.

Используйте подходящую синхронизацию, например `sync.Mutex`, либо передавайте владение данными между горутинами по каналу. Проверять гонки можно запуском тестов с флагом `-race`.

## Короткий список ключевых фактов

- Массив `[N]T` имеет фиксированную длину, которая входит в тип.
- Слайс `[]T` описывает участок базового массива и имеет `len` и `cap`.
- Слайс не является самим массивом; несколько слайсов могут разделять его данные.
- `append` может сохранить или сменить базовый массив; всегда используйте возвращённый слайс.
- Передача слайса копирует дескриптор, а не элементы.
- `copy` копирует элементы, `range` по слайсу выдаёт копию значения элемента.
- Слайсы можно сравнивать с `nil`, но нельзя сравнивать друг с другом через `==`.
