# Создание слайсов с помощью `make`

В Go встроенная функция `make` создаёт слайс и его базовый массив. Для слайса типа `[]T` её можно вызвать в двух формах:

```go
make([]T, length)
make([]T, length, capacity)
```

`length` — число элементов, доступных в слайсе сейчас (`len`). `capacity` — число элементов, которое слайс может охватить от своего начала в базовом массиве без его перевыделения (`cap`). Если вместимость не указана, она равна длине. Все элементы нового слайса получают нулевое значение своего типа; для `int` это `0`.

## Разбор программы

```go
a := make([]int, 5)
```

Создаётся слайс из пяти целых чисел. Длина и вместимость равны `5`, все элементы равны нулю.

```go
b := make([]int, 0, 5)
```

Создаётся слайс нулевой длины с вместимостью `5`. В базовом массиве есть место для пяти `int`, но сейчас ни один элемент не входит в сам слайс. Поэтому при печати `b` отображается как `[]`.

```go
c := b[:2]
```

Из `b` берётся срез от индекса `0` до индекса `2` (верхняя граница не включается). Хотя длина `b` равна нулю, такой срез допустим: верхняя граница `2` не превышает вместимость `b`, равную `5`. Поэтому у `c` длина `2`, вместимость `5`, а элементы равны `[0 0]`.

```go
d := c[2:5]
```

Срез берётся от индекса `2` до индекса `5` относительно начала `c`. Индекс `2` здесь допустим как верхняя граница предыдущего слайса, а `5` не превышает его вместимость. В результате длина `d` равна `5 - 2 = 3`, вместимость — `5 - 2 = 3`. Значения элементов — `[0 0 0]`.

Все слайсы `b`, `c` и `d` относятся к одному базовому массиву. Срезы не копируют элементы: они задают участки массива с собственными длиной и вместимостью.

## Результат работы

```text
a len=5 cap=5 [0 0 0 0 0]
b len=0 cap=5 []
c len=2 cap=5 [0 0]
d len=3 cap=3 [0 0 0]
```

Важно: `len` отвечает на вопрос «сколько элементов сейчас доступно в слайсе», а `cap` — «сколько элементов доступно от начала слайса в базовом массиве». Поэтому слайс может иметь нулевую длину и ненулевую вместимость, а его длину можно увеличить срезом, не выходя за пределы вместимости.
